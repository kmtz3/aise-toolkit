---
name: daily-brief
description: Pull today's meetings + open Planhat Tasks, prep today's unprepped customer sessions by default, flag tomorrow's sessions needing prep, auto-create calendar focus blocks for missing prep, optionally auto-prep tomorrow's sessions (--auto-prep), and render a styled HTML daily briefing page to ~/Desktop/aise-assistant/briefs/ (attached to the chat instead in scheduled cloud runs).
---

Generate a daily briefing page for today (or `--date YYYY-MM-DD`). Arguments: $ARGUMENTS

Read the procedure in the plugin's `agents/daily-brief.md` and execute it inline as the main assistant — do not try to spawn `daily-brief` as a subagent (custom agents in this plugin are procedure documents, not registered subagent types). **Path note:** `agents/daily-brief.md` lives at the plugin root (e.g. `plugins/aise-assistant/agents/daily-brief.md`), not inside the skill subdirectory — use an absolute path or resolve from the plugin root, not relative to `skills/daily-brief/`. **Planhat is the source of truth for this skill** — sessions, prep status, and tasks are all read from Planhat, not Notion (see the agent file's header note for why). The steps:

0. **Detect run mode** (agent file, "Run mode"): no `mcp__remote-devices__*` tools, or a prompt that says "scheduled", means cloud mode: never prompt, and deliver per step 7 below.
1. Resolve user identity — follow Step 1 of `agents/daily-brief.md` exactly (Planhat `custom.AISE Identity` lookup for name/timezone/working hours/`planhat_user_id` — the field is HTML rich text, strip tags before parsing `Key: value` lines). Compute today and tomorrow's date windows.
2. Pull both days' calendar events; classify each (external customer session, **external – attendee only**, internal, focus block) — resolving the Planhat Company per event to check for a vendor/tool-eval mismatch. Attendee only = external organizer, user not the organizer, and a `FW:`/`Fwd:` title or a description starting `fyi` (e.g. a customer's own forwarded community call): badge `👀 Attendee only`, show the Company and its open tasks, and never look up a Task, badge prep, block or prep it. Display every time in the user's timezone from `custom.AISE Identity` (ignore the event's own `timeZone` label) and flag external sessions that start less than 10 minutes after another meeting ends.
3. For today's external sessions: resolve the matching Planhat Task/Conversation **by GCal event ID first**, take the `companyId` from it (name/domain search only when no record is found; on duplicate Companies prefer the one owned by the user and flag it), badge prep status from `custom.Prep Notes`, and extract the topic plus one top-risk line after stripping everything up to and including the first `<hr>`. Risk order: first `🔴` line or `<li>` → first `<li>` under `Watch-fors` / `Risks / watch-outs` → first `<blockquote>` that isn't a booking note; none → no risk line. **Stale prep:** if the date in the prep header differs from the event's start date (user's timezone), badge `⚠️ Prep stale (rescheduled from <date>)`, never `✅ Prep done`. Read the facilitation link from `custom.Facilitation Playbook URL`, else from an `<a href>` ending `_Facilitation.html` in the notes, else a legacy `Drive file:` line.
3.5. **Same-day prep — on by default** (agent step 3.5; `--no-same-day-prep` turns it off). Every one of today's external customer sessions that starts after now (`TZ=<user tz> date`) and is badged `⚠️ No prep`, `— Not in Planhat` or `⚠️ Prep stale` gets the full `session-prepper` procedure inline, soonest first, one at a time, `--unattended` (no ownership prompt, no question; `--force` for stale). Attendee-only events and vendor evals are excluded; sessions within 30 minutes are still prepped and marked ⏰. A, Discovery and Kick off sessions must end with the facilitation guide in Drive and `custom.Facilitation Playbook URL` read back, or show `🔴 Facilitation missing – <reason>`. Afterwards re-read the records, badge them `✅ Prep written this run`, and add `Prepped today: <Customer> <HH:MM> → Planhat Task <_id>` to the chat summary and push notification.
4. For tomorrow's external sessions: flag any missing or stale prep, auto-create a focus block on today's calendar (skip with `--no-blocks`), and — only if `--auto-prep` was passed (it controls tomorrow only) — run the full `session-prepper` procedure inline so the prep brief lands in `custom.Prep Notes` on the Planhat Task, not just a blank calendar block. Every prepped session also publishes its artifacts to Drive and links them back per `context/session-artifact-convention.md`. Resolve the `Customer Session Artifacts` folder once for the whole run (the persisted `Artifacts folder:` ID first, creating only if no owned folder exists) and reuse the ID across sessions.
5. Pull all open Planhat Tasks (`mainType: "task"`, owner = current user) with a **mandatory paging loop** (`LIMIT 200`, `OFFSET` +200 until a page returns fewer than 200 rows, merge). A page often comes back as a saved file path rather than inline rows; load it with `python3` `json.load` and merge it like any other page. Collapse template checklist tasks to one line per Company, normalise `P1`/`High`, and tier: Today (due today/yesterday or high priority) / Overdue / This Week / Later / Stale (>30 days overdue, collapsed). For each external session today and tomorrow, show up to 5 of that Company's open tasks as "Open before this call" (step 6a).
6. **Check this week's delivered external sessions for missing debriefs** (read-only, step 6b of the agent; `--no-debrief-check` skips it). Window is Monday of the current week (previous Monday if today is Monday), the same one `/bulk --debrief` sweeps. Undebriefed and transcript-pending sessions get their own section in the brief and a line in the chat summary, with a pointer to `/bulk --debrief`. The same section lists **open debrief tasks** (`Slack debrief` / `Re-debrief`) grouped by Company with count and oldest date.
7. Render a self-contained HTML page. **CLI:** save to `~/Desktop/aise-assistant/briefs/daily-brief-YYYY-MM-DD.html` (launch in browser with `--open`). **Cowork:** write to the outputs folder and `present_files`. **Scheduled / cloud (no device bridge):** write to the working directory and deliver with `SendUserFile` (`display: attach`), and say in the chat summary that the Desktop copy was skipped because the run had no computer access. The brief itself stays local by default — only upload it to Drive (as `{UserName}_{YYYY-MM-DD}_{SalesforceAccountId|NA}_Brief.html`) if the user asks for it to be filed there.
8. In the chat summary, list every artifact published this run: file name, Drive link, and which Planhat record received the link, plus a Facilitation result per prepped session (✅ link / 🔴 reason / —). Say so explicitly if the Drive folder had to be created or duplicates were found.

Do NOT ask the user for context that's retrievable. Search first, ask once if something is genuinely missing.
